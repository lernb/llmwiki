# 上海服务器迁移实施计划

**类型：** 项目计划
**来源：** 上海服务器迁移实施计划.pdf

本计划详细描述了上海服务器从原有机房迁移至新机柜（3号机柜）的完整实施步骤，涵盖设备上架、上电、服务检查、网络互通验证等环节。目标是将上海侧原网段（192.168.1.0/24、192.168.3.0/24）的业务平滑迁移至新环境，并确保域控、数据库、应用服务正常运行。

## 一、设备上架

### 1. 上架
- 所有服务器统一上架至**3号机柜**。
- 接入电源及[[UPS]]（不间断电源），确保电力供应稳定。

### 2. 接线
- 各服务器接入**机柜交换机**（机架式交换机）。
- 机柜交换机上联至核心交换机，连接端口位于核心交换机的以下接口：
  - #31 - 对应网段：192.168.1.x
  - #33 - 对应网段：192.168.3.x
  - #34 - 对应网段：192.168.4.x

## 二、设备上电

首先确认网络设备（交换机）启动正常，然后按顺序启动服务器。

1. **第一步：虚拟化平台/域控服务器**
   - 确认[[VMware虚拟化平台]]及[[域控AD服务]]启动。
2. **第二步：数据库服务器**
   - 确认[[数据库服务]]（如SQL Server/MySQL）启动。
3. **第三步：业务应用服务器**
   - 确认[[业务应用系统]]各项服务启动。

## 三、服务器检查

### 1. 网络检查
- 检查每台服务器的IP地址、子网掩码、默认网关、DNS配置是否正确。
- 测试服务器能否 ping 通核心交换机网关。
- 检查迁移服务器之间的互通性。

### 2. 域控检查
- 使用 `nslookup` 检查域控DNS解析是否正常。
- 检查[[域控DHCP服务]]是否正常运行。
- 使用 `dcdiag` 命令进行域控状态诊断。

### 3. 应用服务检查
- 检查[[数据库服务]]是否正常连接。
- 检查[[业务应用]]各进程状态。
- 通过浏览器或客户端测试访问登录业务系统。

## 四、网络互通

### 1. 处理防火墙IPSec VPN 上海网段
- 在[[防火墙]]（型号：AF）上删除原上海网段策略（192.168.1.0/24 及 192.168.3.0/24）。
- 上海侧AF（防火墙设备）同步调整IPSec VPN相关配置。

### 2. 检查核心VLAN31/33接口
- 在核心交换机上开启对应VLAN接口：
  ```
  interface Vlan-interface31
  undo shutdown
  interface Vlan-interface33
  undo shutdown
  ```

### 3. 检查IPSec VPN互通
- 检查上海侧AF的IPSec VPN隧道状态是否建立。
- 测试上海PC能否访问迁移后的服务器（ping、远程桌面等）。
- 测试上海PC使用域账号登录域环境。
- 测试上海PC访问登录业务系统。

### 4. 测试内网互通
- 测试内网（总部或其他分支）能否访问上海 192.168.1.x 网段服务器。
- 测试上海服务器能否访问其他各网段（如办公网、生产网）。
- 测试上海服务器与防火墙的连通性（防火墙内网接口IP：172.18.10.40）。
- 测试上海服务器能否正常访问互联网。
