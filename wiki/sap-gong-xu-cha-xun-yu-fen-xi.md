# SAP工序查询与分析

本文档分析了一个复杂的 SAP SQL 查询脚本，该脚本用于获取生产订单（例如 `010000066445`）的所有工序信息，包括常规工序、外发加工工序，以及通过 `UNION` 方式添加的行政、采购等部门的虚拟工序。其核心目的是构建一个完整的工序确认列表（类似于 `CONFIRMANDPRINTLIST`），用于后续的确认、打印或其他业务处理。

## 查询结构概览

整个查询由多个 `SELECT` 语句通过 `UNION` 组合而成：

1. **主查询（`c` 子查询）**：从 SAP 标准生产订单相关表（`AFKO`, `AFPO`, `AFVC`, `CRHD`, `AUFK`）中提取实际工序，并通过左连接 `CONFIRMLIST`、`TGROUP`、`TUSER` 等表，补充确认数量、人员、班组等信息。
2. **6个 UNION 子查询（`c0` 至 `c4`）**：分别对应 **货运部（9910）**、**产品部（9920）**、**行政部（9930）**、**品质部（9940）**、**采购部（9990）** 的虚拟工序，这些部门不直接在生产系统中体现为工序，但业务上需要参与确认。

## 主查询（常规工序）

主查询的核心逻辑：

- 从 `AFKO`（生产订单表头）、`AFPO`（生产订单项目）、`AFVC`（生产订单工序）、`CRHD`（工作中心）关联获取工序号（`vornr`）、工作中心（`arbpl`）、物料号（`matnr`）等信息。
- 过滤条件：
  - 生产订单号 `a.aufnr='010000066445'`。（注释中有按日期过滤的条件被注释掉）
  - 物料号不以 `0000000000003%` 开头，且若非以 `H%` 开头，则必须是物料类型为 `ZFRT` 的物料。
  - 工序状态 `I0013` 必须非“非激活”（即 `INACT` 不为 `'X'`，或状态条目不存在）。
  - 生产订单号以 `01%` 开头。
  - 工作中心属于 `TGROUP` 表中的班组列表，或工作中心以 `WX` 开头（外发加工）。
- 使用 `CASE WHEN` 逻辑根据工序号和工作中心计算 **`GC`（工厂/车间）**：
  - 当工序号小于 `9920` 且工作中心不以 `WX` 开头时，从 `V_FACTORY_NB` 视图中按班组名获取车间。
  - 当工序号小于 `9920` 且工作中心以 `WX` 开头（外发加工）时，根据 `TGROUP` 表中的 `wxgroup` 字段（如“缝制确认”、“拼缝确认”等）从 `V_FACTORY_MIS_WX` 视图中取相应的 GROUPNAME 对应的车间。
- 左连接 `CONFIRMLIST` 表，关联条件是订单号、工作中心和工序号，用于获取已确认的数量（`agvrg`, `lmnga`, `dyzp`, `amnga` 等）以及其他确认信息（`BZ`、`confirmdate`、`autoflag` 等）。
- 左连接 `TUSER` 表获取确认人姓名。
- 左连接 `TGROUP` 表获取班组信息。

## UNION 子查询（虚拟部门工序）

每个虚拟部门工序的查询结构类似，主要包括：
- 固定字段：`ZL`（部门名称）、`GC`（部门名称）、`PXXM`、`groupname`、`SCBM`、`GXMS` 均为部门名称。
- 工序号 `GXBH` 固定（如 `'9910'`）。
- `ARBPL` 固定（如 `'0006HYB'`）。
- 从 `CONFIRMLIST` 表中按订单号和工序号取确认数据（`agvrg` 等）。
- 左连接 `TUSER` 表。

**五个虚拟部门及其工序号：**

| 部门 | 工序号 | ARBPL |
|------|--------|-------|
| 货运部 | 9910 | 0006HYB |
| 产品部 | 9920 | 0007CPB |
| 行政部 | 9930 | 0008XZB |
| 品质部 | 9940 | 0009PZB |
| 采购部 | 9990 | 0007CPB |

注意：采购部的 `ARBPL` 与产品部相同（`0007CPB`），但工序号不同（9990）。

## 脚本中的后续操作

在查询之后，脚本还包含几条独立的语句：

1. `SELECT * FROM it.CONFIRMANDPRINTLIST WHERE aufnr='010000066755'`
2. `DELETE FROM it.CONFIRMANDPRINTLIST WHERE aufnr='010000066755'`
3. `SELECT * FROM CONFIRMLIST WHERE aufnr='010000066445'`
4. `UPDATE CONFIRMLIST SET =0 WHERE aufnr='010000066445' AND ARBPL='0007CPB' and =30`
5. `UPDATE CONFIRMLIST SET =30 WHERE aufnr='010000066445' AND ARBPL='WXFZ'`

这些语句可能是调试或数据修复操作，其中 `UPDATE` 语句缺失了字段名（如 `SET columnname=0` 被写成了 `SET =0`），可能是复制时遗漏。

## 涉及的主要SAP表

- **AUFK**: 订单主数据（订单号、类型等）
- **AFKO**: 生产订单表头（订单号、计划开始日期等）
- **AFPO**: 生产订单项目（物料、数量等）
- **AFVC**: 生产订单工序（工序号、工作中心等）
- **CRHD**: 工作中心主数据（工作中心代码、描述）
- **CONFIRMLIST**: 自定义确认表（存储工序确认数量、人员、时间等）
- **TGROUP**: 班组定义表（`arbpl` 与班组名、外发组类型的映射）
- **TUSER**: 用户表（用户ID、姓名）
- **V_FACTORY_NB**: 视图，用于常规车间查找
- **V_FACTORY_MIS_WX**: 视图，用于外发加工车间查找
- **MSEG/MKPF**: 物料凭证（被注释掉的部分用于获取入库日期）
